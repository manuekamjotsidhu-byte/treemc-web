How to enable offline mode on a Minecraft server (often called cracked mode)

Understand Minecraft offline mode, the online-mode setting, player identity changes and authentication precautions before changing your server.

Looking for the cracked-server switch? On a standalone Java server, the setting people usually mean is `online-mode`. Changing it is simple; understanding what happens to player identity is the part you shouldn't skip.

What the setting actually does

With online-mode=true, the server verifies connecting players against Minecraft's account service. Setting it to false turns that check off. It does not install plugins, improve performance or provide anyone with a Minecraft license.

For an ordinary public server, keeping the official account check enabled is the simpler option. If you need offline mode for a specific setup, test it privately first and understand who will verify player identities instead.

Before you change a live world

Take a complete backup of worlds, player data, permissions and plugin databases. Changing authentication mode can change the UUIDs used to identify players. Existing inventories, permissions and other records may no longer match the identity a player joins with.

Don't rename player-data files at random. Make a migration plan for the exact server and plugins you're using, then test a copy with a non-administrator account. Keep the original backup untouched until the results are clear.

Change a standalone Java server

Stop the server from its control panel and wait until it is fully stopped. Open the server's server.properties file in the file manager or through SFTP. Find online-mode=true, change it to online-mode=false, and save.

Start the server and inspect the console. If a panel startup setting manages this value, the file may be overwritten; check your host's documented controls instead of repeatedly editing the same line. Test joining on an isolated setup before reopening access to everyone. Don't switch off unrelated security options just to suppress an error.

Protect names and administrator accounts

Without account verification, a name alone isn't reliable proof of who joined. A whitelist alone doesn't solve impersonation in offline mode. Before public access, use an authentication setup compatible with your exact server version and review its registration, recovery and administrator-account protection.

Test whether an unauthenticated user can move, run commands or interact with the world. Protect existing staff names before opening registration. A login plugin adds its own maintenance duties; it isn't a reason to hand out operator status freely.

A proxy network needs a different plan

If you're using Velocity or another proxy, follow its complete forwarding and security documentation. Backend servers can use offline mode while the proxy performs authentication, but those backends must not be reachable directly by arbitrary players.

Don't apply a standalone cracked-server tutorial to a proxy network. Confirm the forwarding mode, matching settings and network restrictions together. A working connection doesn't prove the backend is secured.

Test recovery before inviting players

Check inventories, permissions, login recovery and a server restart with your test accounts. If the result isn't right, stop the server and restore the matched configuration and data from the backup. Turning online-mode back to true alone doesn't merge records created under different identities.

When choosing hosting, ask about file access and supported software rather than assuming the cheapest hosting in India includes authentication-plugin setup. Those are separate questions.

Your next steps

  • Back up player data and plugin databases.
  • Test the mode change on a private copy.
  • Check identity protection before public access.
  • Verify inventories, permissions and recovery.

Questions readers ask

Will offline mode make the server faster?

It is an authentication setting, not a performance optimization. Investigate lag separately.

Can I just use a whitelist?

A whitelist doesn't prove ownership of an offline-mode username. Plan authentication rather than relying on names alone.
