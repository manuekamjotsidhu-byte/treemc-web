How to test Minecraft hosting: ping, TPS and a repeatable play session

Test a Minecraft host with a repeatable play session. Separate connection latency from server load and record the conditions behind every result.

By TreeMC · 20 October 2026 · 3 min read

A screenshot of a quiet server is not much of a performance test. If you want to compare hosting, recreate the things your group actually does: exploring, visiting farms, using plugins and returning to a busy spawn.

Prepare a test you can repeat

Use a backed-up test copy of your world where possible. Record the plan, region, Minecraft release, server software, Java version, plugin or mod versions, settings and test date. Keep the world and settings consistent when comparing two configurations.

Agree on an ordinary session length and a small route through representative areas. Have players explore, visit an established base and use the features that usually trigger complaints. Ask the provider before performing synthetic load tests; a normal authorized play session is a safer starting point.

Measure the player connection separately

Ask several players to record their city, internet provider and the in-game connection symptoms at roughly the same time. A provider-supplied test address may help check the route, but an ICMP ping result alone is not a full game-session measurement. Some networks filter or deprioritize those packets.

Repeat during the hours the group normally plays. Record variability and interruptions rather than keeping only the lowest number. If a problem affects one connection, compare that player's local network and route before attributing it to the server.

Use the right server-side tool

For Paper, follow its current profiling documentation and capture a profile while the slowdown is happening. A profile taken while everyone is offline may miss the cause. The documentation explains the available spark workflow for supported Paper versions; check your version before following commands.

TPS describes the server's tick rate and MSPT describes time spent processing ticks. They help explain server-side delays, but neither is the same thing as network ping. Save the observation alongside the player activity and resource readings rather than treating a single number as a complete verdict.

Change one thing and repeat

If the slowdown appeared after adding a plugin, test that hypothesis on the backup copy. Keep the other settings the same and repeat the same activity. If you change the host, server software, view distance and plugins together, you will not know which change made the difference.

Use the lag troubleshooting guide to organize symptoms and the optimization guide for a careful change process. An upgrade is most useful once you can describe the constraint it needs to address.

Publish results that someone else can understand

A useful report includes the configuration, location, workload, number of connected players, dates, method and limitations. Mark results as your measurements, not universal promises. Do not claim that every player in a city will get your exact latency.

Remove private addresses, access details, player information and other sensitive data before sharing logs or profiles. Review what an uploaded profile exposes and use the profiling tool's controls. This article provides a test method; it does not claim that TreeMC or another provider has achieved a particular benchmark.

Your next steps

  • Record the full setup before the session.
  • Collect observations from more than one player connection.
  • Profile during the issue and change one variable at a time.
  • Keep results, dates and limitations together; redact private data.

Questions readers ask

Can low ping coexist with server lag?

Yes. A nearby connection can respond quickly while the server takes too long to process the world. Investigate both the connection and the server workload.

Does this article contain measured TreeMC benchmark results?

No. It describes a repeatable method. Any future published results should identify the exact plan, conditions, date and limitations.
